# 株トレード防衛 Ver.0.9.0（未公開・検証版）

## Ver.0.8からの変更
- SBI証券の信用建玉で、現在値／平均建単価の画面と株数／評価額の画面を銘柄コード・売買区分で照合し、同じ候補行にまとめます（`sbi-parser.js`）。
- 数値に複数候補の不一致があれば欄を空白にし、注意表示と保存の保留を行います。
- 別画面で取得できなかった数値は推測せず空欄を残します。
- 株価・年号などの4桁数字から偽の銘柄候補を増やしにくいよう改善。
- OCR結果の登録前に、株数・平均建単価・現在値・評価額・損益の確認が必要です。

## 安全と制限
- **OCRをiPhoneで検証したわけではありません**。SBIスクショの読み取り・画面の行順は実機で変わり得ます。
- 候補の結合キーは「銘柄コード・売買区分」です。同じコード・売買区分の**複数建日・期限の明細は誤結合の可能性があるため、明細単位での自動登録は未対応**です。
- 依然としてTesseract.jsを外部CDNから初回取得します。画像を送信するアプリコードはありませんが、CDNへの通信は発生します。
- 端末保存データをGitHubへ登録しないでください。ローカルバックアップを先に取ってください。
- このファイルはGitHub Pagesにまだ反映されておらず、公開中のVer.0.1とは別です。

## 確認したテスト
`node --check *.js`（各JS個別実行）、`node test-import.js`、`node test-backup.js`、`node test-sbi-parser.js`。
テスト画像は金融データを含まない合成文字列を使用。実画像のOCR認識精度、Safariでの動作、ブラウザ全操作のE2Eは未検証です。

## 公開時の手順
1. 端末内データをバックアップ（現公開版0.1にはバックアップ機能未実装なので設定・建玉内容を控える）。
2. ZIPを解凍し `index.html`, `*.js`, `manifest.json`, `sw.js`, `icon-*.png` を同一リポジトリのルートにアップロードする。
3. GitHub Pagesが更新されたらSafariでリロードし、表示バージョン0.9.0を確認。ホーム画面アプリは旧キャッシュが残る場合がある。
4. デモ用口座でOCRを試し、画像・テキスト・建玉の認識結果を照合する。
